# OPERATIONS.md · 长任务运行纪律(防止"任务死了几小时没人发现")

## 教训(2026-08-23 实证)

一条 4 小时的链路死了 1 小时才被发现:423 抖动杀死进程、管道吞掉退出码、无心跳、无人巡检。
**完成通知不是兜底,它只是最后一口气。** 以下三层机制强制生效:

## 三层机制

1. **监督器**:任何预计 >10 分钟的任务必须经 `scripts/supervise.sh <名> <命令>` 启动。
   它给 pipefail、失败重试 ≤5 次、状态机文件(`out/<名>.status.json`)、日志(`out/<名>.log`)。
2. **心跳**:被监督任务必须有"活着且在工作"的外部可观测信号。本仓约定以
   `transcripts/transcripts.db` 的行数与 mtime 为心跳(每次 LLM 调用都写)。
   超过 15 分钟无增长 = 疑似卡死。
3. **定时巡检**:编排者(我/任何 agent)必须挂 cron 定期醒来(当前:~每 17 分钟),
   检查:后台任务状态 + status.json + 心跳。异常则诊断并依断点重启;正常则一句简报。

## 配套纪律

- 链式命令必须 `set -o pipefail`(管道吞退出码的实证);
- 任何可中断的长任务必须有断点续跑(如 `pairs build --llm-mid` 的 partial_llm.jsonl);
- 重启必须是幂等/可续的——"重启零损失"才允许自动重试。
