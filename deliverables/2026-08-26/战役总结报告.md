## 第一部分 · 五天长跑总结

### 1.1 战役时间线

**D1（8/21-22）游乐场基建。** 从零搭起免费路径的全部承重结构：CNB swarm 客户端（抢占/投递/轮询/并发闸 48——实测平台硬上限 64）、issue 窗口生命周期管理（≥80 评论退役自动补开，单 issue 100 评论封顶）、打包投票协议（5 组对比一条评论，对抗"评论进上下文"的污染）、原子占窗防并发撞窗。契约层：可变面/只读面/运行器三分，champions.yaml + promotion 规则 + optimizer/notebook 台账格式。当天教训：35 个窗口因超限被锁死——免费资源的配额不是细节，是架构约束。

**D2（8/23）判官考试：先信考试，再信分数。** 造"判官考试"——用已知缺陷的文本对测判官灵敏度。六轮迭代（v1→v6）打掉三个测量级陷阱：
- **评估器缺陷伪装成被评对象缺陷**：语料锚是制作信息表残片，判官当然偏爱生成物——首考 naturalness/l0_dialogue 灵敏度 0.00，不是判官瞎，是考题脏；
- **corpus_vs_gen 系统性反向**：判官对生成文本的偏爱与"偏离带=劣"的标签方向相反，此类对全部逐出考场；
- **验真过滤**：退化算子构造的缺陷必须可测量地真的落进去了才能进考场（D06/D11 无验真器不入场）。
最终判官闸门成绩：transportation 灵敏度 0.89（过 0.85 门限）、placement 0.77、l0_dialogue 0.75。**判官天花板 = 随机后端能力上限，不是工程问题**——运营决策：三轴判分面，其余只报告。

**D3（8/24）shim 网关 + 管线首通尝试。** OpenAI 兼容 shim 把 CNB 集群接成 SW 的 LLM 端点（代码零改动），JSON 抢救 + 毒化重试 + 流量取证日志。SW 管线开始真实跑批——这一天是"死亡博物馆"：p0 JSON 拒答、STR-018 升级缺失、PENDING 伏笔悬空、类型漂移、null 字段崩校验、空角色表、对白欠量……每个死因当天修复（先写测试），attempt 计数器一路涨到 80+。

**D4（8/25）修复链高潮：从"活不过编译"到"全绿产物"。** 七轮 harness 硬化（round14-18，详见交付报告 §3.1）：结构机械修复器、时长等比缩放、传输容错、对白区间对齐+当场扩写、p6 prompt 瘦身、暗线钳制。8/25 18:10，**首个完整产物《下午三点》落地**（8 章小说 26k 字 + 8 集剧本 29k 字 + 溯源 manifest）；19:00 前完成三轴判分，champion v1 刻印（0.708/0.929/1.0）。方法论在这一天定型：**弱随机后端上，结构性约束一律机械兜底，LLM 指令只负责语义质量**。

**D5（8/26）题材迁移实证 + 交付。** 用户定稿南浪仔（海南文旅 IP）五幕故事，harness **零学科特判**直接承接——只新增 brief/brand 两份资产。新打两门：BM-009 canonical 资产设计失误（100% 拦截先怀疑规约）、ir.json 导出 datetime bug（全绿产物死于最后一步）。产物《南浪仔》落地并判分（0.73/0.955/0.929），champion v2 刻印；同产物两跑判分测出**判官噪声带 ±0.02-0.05**。08:00 交付包准时就绪，后续为加赠时间。

## 第二部分 · 问题、经验与未来游乐场蓝图

### 2.1 问题清单（按层归类，全部有实证出处）

**测量层**
- 判官系统性偏差：对生成文本有偏爱、对语料锚有劣势（corpus_vs_gen 反向实证）→ 绝对分不可信，只有纵向差值可用；
- 判官噪声带 ±0.02-0.05（同产物两跑实测）→ 晋升阈值必须大于噪声带，否则在拟合噪声；
- 判官灵敏度 = 后端能力上限（0.75-0.89）→ 弱判官评不出比自己好太多的东西；
- sealed 判官缺位（零预算约束）→ 存在"自己人改自己人卷子"的残余风险。

**生成层（弱后端行为图谱）**
- 毒化三模式（约 3% 每请求）：散文拒答、`...` 占位/schema 复述（以 `{` 开头骗过浅检）、JSON 外裹散文；
- 系统性欠量：对白体量稳定欠 26%，重试不治（分布问题不是方差问题）；
- 结构约束彩票化：枚举/间距/出席/承重节拍的遵守率逐次独立，相位重试 = 反复抽同一张彩票；
- 时长预算假账：est_duration_s 系统性低估，下游一切换算跟着错。

**工程层**
- 免费沙箱的三座大山：并发硬上限（64）、单窗口评论封顶（100）、评论进上下文（污染）——全部转化为架构约束而非运维事故；
- 传输故障杀死整轮（2.5h 陪葬一次 shim 重启）→ `_retry_pass` 传输容错；
- Windows 进程管理陷阱：Git Bash PID ≠ Windows PID、TaskStop 只杀壳留孤儿、模式匹配误杀自己（两条命案）；

**资产层**
- canonical 命名设计失误使品牌 slogan 本身违规（BM-009 100% 拦截）→ **拦截率 100% 时先怀疑规约，再怀疑被规约的对象**（与判官考试"评估器缺陷伪装成被评对象缺陷"同构）。

### 2.2 经验十条（每条都是血泪换的）

1. **结构约束机械兜底，指令只管语义。** 战役全部净提升来自确定性修复器，零来自 prompt 调优（prompt 轮还没开打就跑通了——顺序本身就说明问题）。
2. **先信考试，再信分数。** 任何度量上线前先考度量本身；灵敏度、位置偏差、噪声带三个数必须有。
3. **先取证，再修复。** shim 流量日志一次就位后，毒化模式从"猜"变成"看"——每个修复都有实证出处，零臆测修复。
4. **门禁即产品。** 82 条声明式门禁不是成本中心，是"可解释的工业化的好"这个商业模式的证据链本体。
5. **彩票换确定性。** 弱后端的每一次"可能遵守"都要问：能不能变成"必然成立"？（归一/钳制/重排/替换/缩放五板斧）
6. **监督循环无人值守化。** supervise（重试≤5+状态文件+日志）+ cron 巡检（心跳分阶段判活）+ 事件驱动唤醒，让 3 天无人值守零事故。
7. **晋升规则外置。** 优化器（哪怕是自己）不能给自己批卷子——per-axis 地板 + 噪声带阈值 + champion 注册表，全部在优化器写不到的地方。
8. **失败语料库是复利最强的资产。** 90 次 attempt 的死因全部留痕（commit message/台账/日志），后续优化的真实先验都在这里。
9. **上下文即预算。** 打包投票、窗口退役、原子占窗——免费路径下每一KB上下文都要记账。
10. **杀进程先确认父子关系。**（半开玩笑，但两条命案是真的）

### 2.3 未来游乐场蓝图（强模型 PM 带弱模型工人）

如果要从零再建一个这样的系统，按这个顺序：

**第 0 层 · 契约（先于一切代码）**
五件套：①优化目标（分层指标+聚合规则）②可变面（优化器能改什么，声明式+进 git）③预算（token/窗口/并发/人工注意力，全部配额化）④数据边界（dev/val/sealed 三分，sealed 物理只读）⑤评测（先考度量本身，再允许它打分）。**OEO 论文的正确用法**：契约外置，"怎么改进"放权给强模型；晋升规则永不下放。

**第 1 层 · 后端无关的接入层（shim 模式）**
任何 LLM 来源（免费沙箱/弱 API/本地小模型）都包装成 OpenAI 兼容端点 + 四件事：输出抢救（JSON 提取）、毒化侦测重试、逐请求流量取证、长度护栏。被优化系统代码零改动——**后端是可替换电池**。

**第 2 层 · 判官体系**
- 判官考试先行（退化对+验真过滤+双向位置交换+打包投票）；
- 三轴判分面 = 考试验证过灵敏度且彼此低相关的最小集合；
- dev/sealed 双判官（sealed 是唯一的真分数，配额提交）；
- 噪声带实测入库，晋升阈值 > 噪声带；
- 人机一致率定期复测（度量腐坏的唯一预警）。

**第 3 层 · 生成 harness 的"可优化形态"**
- 流程=相位+门禁+相位内带诊断重试；
- 可变面全声明式（prompts/profiles/资产进 git，content_hash 溯源）；
- 机械兜底层与 LLM 层物理分离（兜底层是确定性代码+测试，永不让模型碰）；
- 每个产物带 manifest（谁/什么版本/哪次调用生的它）。

**第 4 层 · 监督与台账**
- supervise 包装一切长任务（重试/状态/日志）+ cron 巡检（心跳分阶段）+ 事件驱动；
- optimizer notebook：每轮一条（假设/变更/结果/决策），格式不合规视为未发生；
- champion 注册表：唯一真相源，只增不改。

**PM（强模型）的工作界面**：读门禁诊断 → 判定"结构 or 语义" → 结构写机械修复（先测试）/语义改 prompt → 跑批 → 判分 A/B → 晋升或回滚 → 台账。PM 不碰：门禁、判分程序、sealed 数据、晋升判定。
**工人（弱模型）的工作**：批量生成、初评投票、退化构造——一切"错了可以再来"的活。
**绝对分工原则：判断对错的事不给弱模型，需要创造的事不给门禁。**

## 第三部分 · 成熟度评估（相对纯合成数据上限）

### 3.1 评估框架

质量能力分四层，各层"合成数据上限"位置不同：

| 层 | 内容 | 合成路径上限 | 当前位置 |
|---|---|---|---|
| L0 结构合规 | 82 条确定性门禁（结构/品牌/对白/伏笔/合规/一致性/状态） | 100%（机械可达） | **≈95%**（全绿产物连续产出；FCT-001 自造数字尚无机械兜底） |
| L1 自动标量 | 体量/重复率/语音指纹/自相似度 | 100%（机械可达） | **≈60%**（DLG 系列在线；自相似度、节奏曲线等未建制） |
| L2 LLM 判官 | 三轴成对比较 | **判官能力本身**（随机后端 0.75-0.89 灵敏度 + ±0.02-0.05 噪声带） | **≈55%**（dev 判官可用，sealed 缺位，系统性偏差已量化未消除） |
| L3 人类/市场 | 完播/转化/追读 | **合成路径不可达** | 0%（按计划留白） |

### 3.2 生成质量的合成上限与当前位置

**合成上限的定义**：随机后端模型池的生成能力 × harness 放大系数 × 判官可分辨精度。三者中最脆的是判官——**弱判官评不出比自己好太多的东西，所以纯合成路径的质量天花板，就是"弱判官勉强还能分辨优劣"的那个质量点**。

**当前位置估算：合成上限的 55-70%。**
- 已封顶的部分：结构合规（L0）、题材迁移能力、可解释性（manifest+门禁证据链）——这些是 harness 的成就，与模型能力无关，已经站在上限上；
- 未封顶的部分：语义质量。transportation 0.708-0.73（对语料锚）说明代入感与真人语料还有可分辨差距；已知语义缺陷清单未修：对白 tic 重复（「咱就是说」单角色单集 5+ 次）、伏笔回收记账（FCT-003 建议级）、钩子回应（STR-016）、场景成本超标（PRD-001）。这些都在判官量程内、都有明确修法——**这就是到上限之间那 30-45% 的具体内容**；
- 到不了的潜力：文笔的"上限突破"。就算修完已知缺陷，产物质量也不会显著超过随机后端的母语水平——这是合成路径的物理边界。

### 3.3 到合成上限的路径（预计 2-4 周，按 §5 假设排期执行）

1. **sealed 判官补位**（1 周，需一个付费 key）：跨家族校验 + 重刻基线——这是"上限测量"的前提，没有它连"到没到上限"都无法判定；
2. **语义缺陷歼灭战**（1-2 周）：tic 去重（机械计数器+指令）、伏笔/钩子回收记账（p2 机械校验）、L1 指标补全（自相似度/节奏曲线）——全部有现成打法；
3. **M1 指令优化轮**（1 周）：transportation 主攻（唯一有量程的轴），严格走"变更→跑批→同池判分→噪声带外才晋升"。

### 3.4 真实世界数据接棒的接口（已预留）

- **判官校准**：真人成对标注 300-500 组（小规模即可），测 sealed 判官与人一致率 ≥0.7 才继续信任它；平台完播/流失数据到手后，判官 rubric 按真实信号重加权；
- **retrieval 层**：pipeline 已带 `_retrieved`（案例库检索），真实爆款入库即成为生成先验，harness 无需改动；
- **奖励模型**：判官的成对偏好数据（本战役已积累数千条）+ 真实平台信号 = reranker 训练数据，best-of-n 成本/质量曲线跃迁的标准打法；
- **失败语料库**：本战役 90 次死因 + 后续真实客户打回，全部转带自动检测器的回归用例。

**一句话**：合成路径负责把"工业化的好"做到可解释、可复现、可迁移（已完成 ~2/3），真实数据负责把"好"的定义权从判官手里交给观众——两个阶段的接口已经焊好。
