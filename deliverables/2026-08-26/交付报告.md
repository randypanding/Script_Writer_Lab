## 2. 成品为什么好（可解释的工业化质量）

这个商业模式卖的不是"AI 写了篇小说"，而是**"每一处好都指得出证据"**。证据分三层：

### 2.1 L0 硬门禁：47+ 条确定性规则全绿

成品通过的不是一个模糊的"AI 觉得好"，而是一整套可执行的出厂质检（`Script_Writer/spec/checks/`，按域分组）：

- **结构**：每集必有引爆（inciting）+ 高潮（climax）承重节拍（STR-014）；主角每集出场（STR-010）；冲突强度逐集递进（STR-018）
- **品牌**：植入与剧情融合度分级、植入间距 ≥2 拍（BM-002）、必提台词原文出现（BM-007）、竞品名零出现（BM-011）
- **对白**：总字数匹配时长预算 ±15%（DLG-006，90 秒集 = 344-466 字）；角色语音指纹命中率（DLG-004）
- **伏笔**：埋设/回收配对、悬空伏笔预警（FCT-003）、集末钩子 3 集内必回应（STR-016）
- **合规**：广告绝对化用语零出现（CMP-001，对接广告法词表）；产品参数必须来自 BrandBrief 事实表，自造数字即拦截（FCT-001）
- **小说-剧本一致性**：两个视图必须是同一个故事（NOV-002 相似度门）；每拍对白必须逐字织入小说（NOV-001 锚点覆盖）
- **状态一致性**：叙事暗线阶段推进不越界（INV-19）

**关键工程事实**：这些门禁不是摆设——在本次战役中它们真实拦截了 10+ 次不合格产物，而修复链（见 §3）让成品从"连门都过不了"走到"全绿"。

### 2.2 三轴判分：独立判官的成对比较

判分面 = 经过"判官考试"验证灵敏度最高的三条轴（考试方法：构造已知缺陷的文本对，测判官能否检出，灵敏度门槛 0.85）：

| 轴 | 含义 | v1《下午三点》 | v2《南浪仔》 |
|---|---|---|---|
| transportation | 代入感/沉浸 | 0.708（winrate 0.50） | 待填 |
| placement_integration | IP/品牌融入自然度 | 0.929（winrate 0.86） | 待填 |
| l0_dialogue | 对白质量 | 1.00（winrate 1.00） | 待填 |

方法：产物切片 vs 同轴语料锚（真实剧本语料库），**双向位置交换 × k=5 采样 × 打包投票**，判官是 CNB 集群的随机后端模型（与我们生成用的后端同池但独立会话）。

**判分纪律（重要，防自欺）**：
- 语料锚对 LLM 判官有系统性劣势（考试期实证），**绝对分偏高，只有同池同程序的纵向差值有意义**；
- l0_dialogue 已触顶，该轴无改进量程，只作防降级地板；
- sealed 判官（跨家族模型校验）因零预算约束缺位——这是当前测量体系的最大缺口，见 §5。

### 2.3 可解释性的最后一环：manifest.json

每个产物带 D20 溯源清单：每个节拍、每句台词、每个植入对应的 spec 版本、prompt 版本、模型调用 ID。客户问"这段为什么这么写"，能指到具体的设计决策。

## 3. 相比之前的提升

### 3.1 从"跑不通"到"全绿"：round14→20b 修复链

战役起点（8/24 晨）：管线在任何真实生成下都活不过编译阶段，从未产出一件完整产物。
战役终点（8/26 晨）：连续产出完整 8 集短剧 + 小说，门禁全绿。

| 轮 | 打掉的失败模式 | 方法 | 实证 |
|---|---|---|---|
| r14 | STR-014/BM-002/STR-010 结构三杀（连死 2 轮 × 1.5h） | p3/p4 机械修复器（承重节拍兜底/植入重排/主角补位） | attempt4/5 日志 |
| r15 | DLG-006 根因①：时长预算假账；shim 重启杀死整轮 | est_duration_s 等比缩放；`_retry_pass` 传输容错 | attempt1/2 |
| r16/16b | DLG-006 根因②③：目标区间低于门禁 + NPC 系统性欠量 26% | 区间对齐门禁+余量；`_expand_if_thin` 当场定点扩写 | attempt3/1，失败从 8/8 集→3 集毫厘 |
| r17 | p6 prompt 46k 字符撞护栏（首达 p6 即死） | 三处瘦身投影 + 护栏 20k→60k | attempt2 |
| r18 | INV-19 暗线状态溢出（8 章全产物死于 final 门） | 跨集累加钳制 | round17 attempt1 |
| r19 | CMP-001「唯一」绝对化用语；p1 必填字段空串 | 合规词机械替换表；空串占位 | round18 attempt2/1 |
| r20b | DLG-006 最后 12 字的毫厘之死 | 瞄准余量 +3pp→+6pp，扩写上限 2→3 | round18 attempt3 |

**核心方法论（整个战役最重要的一条经验）**：
> 弱随机后端上，**结构性约束（枚举/间距/出席/预算/合规词）一律机械兜底，LLM 指令只负责语义质量**。相位重试治不了系统性缺陷——模型会轮轮复述同一份诊断而结构纹丝不动。每一轮的打法都是：门禁报错 → 判定"结构 or 语义" → 结构就写确定性修复器（先写测试），语义才改 prompt。

### 3.2 测量系统的副产品

- **判官考试体系**（judgekit + degrade 验真对）：打包投票、信号级分解、双向位置交换；v6 成绩 transportation 灵敏度 0.89。
- **shim 流量取证**（`out/shim_traffic.jsonl`）：发现 NPC 三类毒化模式（散文拒答/`...` 占位/schema 复述，约 3% 毒化率）并全部纳入重试通道。
- **失败模式语料**：每一次 attempt 的死因都记录在台账与 commit message，是后续优化的真实先验。


**仓库分工**（用户定的边界）：
- `Script_Writer` = 可交付软件（harness、spec、门禁、prompts、profiles、品牌/brief 资产）；
- `Script_Writer_Lab` = 游乐场基础设施（swarm/shim/判官/考试/台账/本文档），私有仓 randypanding/Script_Writer_Lab。

**优化面**（按本轮实证的有效性排序）：
1. **机械兜底层**（pass 内的确定性修复器）：本轮全部提升来自这里。新结构性失败模式出现时首选。
2. **M1 指令层**（`prompts/*.json` + spec/passes/contracts.yaml）：语义质量（文笔、tic 重复、代入感）的主战场，尚未开打——这是接手后的第一批实验。
3. **M2 结构层**（profile 旋钮：相位/重试/上下文组成/检索 top_k）：已暴露的旋钮在 `profiles/*.yaml` 的 `pipeline:`/`context:`/`revise:` 段。
4. **判分层**（criteria/、judge 程序、语料池）：测量系统本身的优化（见 §5）。

## 5. 下一批优化假设（按期望值排序，供接手排期）

1. **sealed 判官补位**（测量缺口，最高优先）：当前只有 dev 判官（CNB 随机后端自评），存在"自己人改自己人卷子"风险。有任一付费 key 后：配跨家族 sealed 判官，重刻基线，此后晋升以 sealed 为准。
2. **transportation 指令优化**（唯一有量程的质量轴）：p6 散文的代入感指令——具体手法候选：感官细节配额、内心独白比例、段落节奏方差要求。A/B 用 judge_artifact 同池判分。
3. **对白 tic 去重**：v1 实证「咱就是说」单角色单集出现 5+ 次（DLG-004 建议级）。p5 指令加"同一口头禅单集至多 2 次"+ 机械计数器。
4. **FCT-003/STR-016 伏笔钩子回收记账**：目前建议级不阻塞，但悬念链完整性是网文留存的关键指标。指令+p2 记账机械校验。
5. **语料池扩编与判官校准**：l0_dialogue 触顶说明该轴区分度耗尽——换更难的对比对象（优秀网文片段而非制作表残片），重建量程。
6. **成本/时长优化**：单集 ~40 分钟（CNB 路径）。p5 扩写、p6 是最贵节点；candidate：p3-p5 的 prompt 瘦身（p6 已做）、相位重试改定向重试。
7. **小模型**（用户原始问题，延后但给结论）：当前无必要。判官蒸馏的前提是有稳定判官输出分布（随机后端每日变化），reranker 的前提是有付费生成路径。零预算约束下小模型没有训练数据来源，投产比为负。约束解除后按 评委蒸馏→reranker→抽取器 顺序上。

## 6. 操作规程（接手人日常）

**跑一个产物**：
```bash
cd Script_Writer_Lab && bash scripts/supervise.sh <任务名> bash -c \
  "set -o pipefail; cd /d/Projects/Script_Writer && OPENAI_API_KEY=dummy NSC_NO_CACHE=1 \
   uv run nsc run examples/<品牌>/brief.yaml --profile lab_smoke_v1"
```
（前置：shim 常驻 `bash scripts/supervise.sh shim_service uv run python -m lab.cnb_shim`）

**判分一个产物**：
```bash
uv run python scripts/judge_artifact.py "D:/Projects/Script_Writer/out/<标题>" <tag> --pairs 20 --k 5
```
报告落 `out/artifact_judge_<tag>.json`。per-axis 不低于现任 champion 即在 `champions.yaml` 刻新 champion（晋升须同时满足：无新门禁失败 + transportation 不降级）。

**加一条新门禁**：`spec/checks/<域>/<ID>.yaml`（声明式 DSL，见同目录范例）→ 全量测试 → 台账记录。

**新品牌/故事**：复制 `brands/demo_tea/` 与 `examples/demo_tea/brief.yaml` 模式；注意 banned_words 不得与 products.facts 冲突（有自检惯例）。

**故障处理**（docs/OPERATIONS.md 为真相）：
- 管线卡死判定：runs.db-wal mtime 15 分钟无增长；
- 杀进程必须 `powershell -c "taskkill /PID <根PID> /T /F"` 整树杀，且先确认父子关系（Git Bash PID ≠ Windows PID，模式匹配会命中自己的查询进程——加 `-notmatch 'Get-CimInstance'` 过滤）；
- supervise 包装的命令死后自动重试 ≤5 次，补丁累积生效，完成概率单调上升；
- shim 流量取证：`out/shim_traffic.jsonl`（每个请求的 prompt 长度/重试次数/回复头尾）。

**纪律红线**（违反=优化作废）：
- 门禁只增不改；要让产物过门，改产物侧（生成/修复器），不改检查器；
- 判分程序/语料池/考题为只读资产，改动视同换度量衡，必须重刻全部基线；
- 每轮一个变更 + 台账记录（假设/变更/结果/决策），格式不合规的轮次视为未发生。

## 7. 已知未验证事项（诚实清单）

- sealed 判官缺位：所有质量分都是 dev 判官（随机后端）口径，未做跨家族校验；
- 判官对语料锚有系统性偏爱，绝对分不可外推，只有纵向差值可用；
- v2《南浪仔》的判分基于与 v1 相同的语料池，两产物题材不同（茶饮 vs 文旅 IP），轴分对比需谨慎解读；
- FCT-001（自造数字）目前靠概率与相位重试，无机械兜底——南浪仔 facts 无数字，风险低但未根除；
- CNB 随机后端每日漂移：同一 harness 不同日期的产物质量不可直接比较（判分在同一时间窗内完成可缓解）；
- 判官考试 v6 只有 transportation 过了 0.85 门限，placement/l0_dialogue 灵敏度 0.75-0.77——三轴判分面是运营决策而非满分结论。
